# BUG-001: Reference Resolution Fails with Relative URLs

## Description

Reference resolution was failing when using relative URLs in FHIR resources, causing unresolved references and potential data integrity issues.

## Details

- **Priority**: High
- **Status**: Resolved
- **Assigned To**: Core Team
- **Created Date**: 2025-05-15
- **Resolved Date**: 2025-06-01
- **Fixed In Version**: 1.0.0

## Background

When FHIR resources contain relative references (e.g., `Patient/123` instead of `https://example.com/fhir/Patient/123`), the reference resolution system was failing to correctly resolve these references. This issue was particularly problematic in bundles where resources reference each other using relative URLs.

## Root Cause

The URL handling logic assumed that all references would be absolute URLs. When relative URLs were encountered, the system attempted to resolve them as if they were absolute, leading to failed HTTP requests.

## Solution

Updated the URL handling logic to:

1. Detect if a reference URL is relative
2. Combine relative URLs with the base URL from the client configuration
3. Support both relative references with and without resource type (e.g., "123" and "Patient/123")
4. Add proper URL normalization to handle edge cases like trailing slashes

## Implementation Details

The fix was implemented in the `src/middlewares/references.js` file:

```javascript
// Before
const resolveReference = (ref, baseUrl) => {
  return ref.startsWith('http') ? ref : null; // Only handled absolute URLs
};

// After
const resolveReference = (ref, baseUrl) => {
  if (ref.startsWith('http')) {
    return ref; // Absolute URL
  }
  
  // Handle relative URLs
  const normalizedBase = baseUrl.endsWith('/') ? baseUrl : `${baseUrl}/`;
  
  if (ref.includes('/')) {
    // Resource type included (e.g., "Patient/123")
    return `${normalizedBase}${ref}`;
  } else {
    // Only ID provided, need context for resource type
    return `${normalizedBase}${context.resourceType}/${ref}`;
  }
};
```

## Testing

All test cases now pass, including:

- Absolute reference URLs
- Relative reference URLs with resource type
- Relative reference URLs without resource type
- References in bundles
- References with unusual formatting (extra slashes, etc.)
