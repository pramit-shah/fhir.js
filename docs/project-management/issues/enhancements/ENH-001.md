# ENH-001: React/Vue Component Wrappers

## Description

Create React and Vue component wrappers for common FHIR operations to facilitate easy integration into modern frontend applications.

## Details

- **Priority**: Medium
- **Status**: Under Consideration
- **Proposed By**: Community
- **Created Date**: 2025-06-10
- **Target Version**: 1.2.0

## Background

Many users are integrating fhir.js into modern frontend frameworks like React and Vue. Having official component wrappers would simplify this integration and provide a consistent pattern for handling FHIR operations within these frameworks.

## Requirements

### React Components

1. Functional components with hooks for common FHIR operations:
   - `useFhirSearch`: Hook for search operations
   - `useFhirResource`: Hook for CRUD operations on a single resource
   - `useFhirTransaction`: Hook for transaction bundles
   - `useFhirMetadata`: Hook for capability statement

2. Context provider for FHIR client configuration:
   - `FhirProvider`: Sets up FHIR client configuration for child components
   - `useFhirContext`: Hook to access the FHIR client in any component

### Vue Components

1. Composition API functions:
   - `useFhirSearch`: Composition function for search operations
   - `useFhirResource`: Composition function for CRUD operations
   - `useFhirTransaction`: Composition function for transaction bundles
   - `useFhirMetadata`: Composition function for capability statement

2. Vue plugin for global configuration:
   - `createFhirPlugin`: Creates a Vue plugin with FHIR client configuration

## Technical Approach

1. Create separate packages for framework-specific implementations:
   - `fhir-react`: React components and hooks
   - `fhir-vue`: Vue components and composition functions

2. Keep core FHIR functionality in the main package:
   - Framework wrappers should be thin layers over the core library
   - Avoid duplicating logic across different framework implementations

3. Focus on developer experience:
   - Automatic type inference from FHIR resources
   - Loading and error states handled automatically
   - Optimistic updates with rollback
   - Request deduplication and caching

## Example Usage (React)

```jsx
import { FhirProvider, useFhirSearch, useFhirResource } from 'fhir-react';

// App setup
function App() {
  return (
    <FhirProvider baseUrl="https://hapi.fhir.org/baseR4">
      <PatientList />
      <PatientDetail id="123" />
    </FhirProvider>
  );
}

// Patient list component
function PatientList() {
  const { data, isLoading, error, refetch } = useFhirSearch({
    resourceType: 'Patient',
    params: {
      family: 'Smith',
      _count: 10
    }
  });
  
  if (isLoading) return <div>Loading...</div>;
  if (error) return <div>Error: {error.message}</div>;
  
  return (
    <ul>
      {data.entry.map(entry => (
        <li key={entry.resource.id}>{entry.resource.name[0].family}</li>
      ))}
    </ul>
  );
}

// Patient detail component
function PatientDetail({ id }) {
  const { data, isLoading, error, update } = useFhirResource({
    resourceType: 'Patient',
    id
  });
  
  if (isLoading) return <div>Loading...</div>;
  if (error) return <div>Error: {error.message}</div>;
  
  const handleNameChange = (newName) => {
    update({
      ...data,
      name: [{ family: newName }]
    });
  };
  
  return (
    <div>
      <h1>{data.name[0].family}</h1>
      <input 
        value={data.name[0].family} 
        onChange={e => handleNameChange(e.target.value)} 
      />
    </div>
  );
}
```

## Example Usage (Vue)

```vue
<script setup>
import { useFhirSearch } from 'fhir-vue';

// Patient list component
const { data, isLoading, error, refetch } = useFhirSearch({
  resourceType: 'Patient',
  params: {
    family: 'Smith',
    _count: 10
  }
});
</script>

<template>
  <div v-if="isLoading">Loading...</div>
  <div v-else-if="error">Error: {{ error.message }}</div>
  <ul v-else>
    <li v-for="entry in data.entry" :key="entry.resource.id">
      {{ entry.resource.name[0].family }}
    </li>
  </ul>
</template>
```

## Benefits

1. Simplified integration with modern frameworks
2. Consistent patterns for handling FHIR operations
3. Reduced boilerplate code for applications
4. Better type safety with TypeScript
5. Optimized rendering and state management

## Considerations

- Maintenance burden of multiple framework-specific packages
- Keeping framework wrappers in sync with core library updates
- Versioning strategy for framework wrappers
- Testing strategy across different frameworks
